# showTime 0.8.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use `- [ ]`.

**Goal:** Ship 0.8.0: network record/replay (HTTP + WebSocket), locales, and studio timing by hand
(speed and caption-length dragging, freezes).

**Architecture:** Same layers. New pure modules: `src/script/locales.ts` (localize),
`src/runner/replay-core.ts` (matching, WebSocket schedule, secret stripping). New I/O module:
`src/runner/replay.ts` (Playwright routes, file). Timeline: `captionMs`, `freezeMs` in build.
Studio client: drag handles and a caption track.

**Spec:** `docs/superpowers/specs/2026-10-14-showtime-0.8-design.md`

## Global Constraints

- Scripts without `replay`/`locales` behave exactly as in 0.7; the action hash is unchanged by the
  new fields (`replay`, `captionMs`, `freezeMs`); localized scripts hash per locale.
- `src/timeline/**`, `src/script/locales.ts`, `src/runner/replay-core.ts` stay pure.
- No request headers or credential-like query values reach the replay file.
- Every user-visible error starts with what failed and says what to do.

## Review Focus

1. Replay with a client that sends fewer or more binary frames than recorded: frames still arrive,
   commands (`finalize`) still release theirs, nothing hangs.
2. Concurrent identical HTTP requests in a different order than recorded: each gets an answer, the
   right one where the body differs.
3. A failed or interrupted run in `auto`/`record`: the old replay file is untouched.
4. Localized objects that look like ordinary objects (a `show` with keys `en`/`uk` that aren't
   locales), nested localized values, `{locale}` in targets and URLs.
5. Dragging a step to a length that needs a speed beyond 0.25–16×; dragging during playback.
