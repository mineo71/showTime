# showTime 0.5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use `- [ ]`.

**Goal:** Ship 0.5.0: `showtime studio` (live preview, step timeline, inspector, saves to the
JSON, live reload, render/record from the page) and `showtime record-human` (record a flow by
hand into a script).

**Architecture:** Studio = `src/studio/server.ts` (node:http, guard, routes, SSE, file watch, jobs)
+ `src/studio/client/*` (React, bundled at start with esbuild; reuses `ShowtimeVideo` via
`@remotion/player`) + pure `src/studio/edit.ts` and `src/studio/guard.ts`. record-human =
pure `src/human/convert.ts` + `src/human/record.ts` (Playwright `context._startRecording`).

**Tech Stack:** + `@remotion/player` 4.0.535, `esbuild` ~0.28 (already present via tsx).

**Spec:** `docs/superpowers/specs/2026-10-13-showtime-0.5-design.md`

## Global Constraints

- `src/timeline/**` stays pure; `src/studio/edit.ts`, `src/studio/guard.ts`, `src/human/convert.ts`
  are pure too (no I/O).
- The studio binds 127.0.0.1 only; every `/api/*` request passes the host and token guard.
- The studio never writes a script that fails validation; writes are atomic.
- Every user-visible error starts with what failed and says what to do.
- 0.4 scripts and takes keep working; the renderer output is unchanged when `assetBase` is unset.

## Review Focus

1. The agent rewrites the script while the person edits in the studio: no lost write, no crash,
   the page shows the newest file.
2. An edit that makes the take stale (`hold`) or a script made invalid on disk: the page keeps the
   last good preview and says what to do.
3. A request from another website (no token, wrong Host, path traversal in `/files`) is refused.
4. record-human on a page with an iframe, a popup or a file input: skipped with a note, no crash;
   closing the window always writes the script.
5. Selector rewriting never produces a selector that resolves differently from the recorded one.
