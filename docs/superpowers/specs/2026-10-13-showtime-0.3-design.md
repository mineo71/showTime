# showTime 0.3.0: design

Status: approved for implementation (the user asked for "0.3.0 with all of that": items 1–3 of the
improvement list). Builds on [the MVP design](2026-10-13-showtime-design.md); everything there still
holds unless this document changes it.

## 1. Goals

1. **A cheaper, smarter agent loop.** The agent reviews one contact sheet instead of a dozen
   stills, gets automatic quality warnings, and every command speaks JSON.
2. **Real apps stop breaking takes.** State can be reset between rehearsal and take, flaky APIs can
   be mocked, the clock can be frozen, a failed re-take never destroys the last good take, and
   streaming connections, native dialogs and relative URLs behave.
3. **More polish with less effort.** Captions never collide or cover the action, videos can end on
   a call-to-action card, and a project-wide brand file (logo, colours, outro) applies to every script.

Not in 0.3.0: narration/audio, vertical and GIF formats, a studio UI, human-recorded scripts,
popups/new tabs, virtual-time capture.

## 2. Agent loop

### 2.1 Contact sheet

`showtime frames <script>` keeps writing one PNG per QA shot and now also writes
`.showtime/<name>/frames/sheet.png`: every shot as a thumbnail in a 4-column grid, labelled with the
shot name, on a dark background (1920 px wide, thumbnails 456 px wide). Human output prints the sheet
path first, then the stills. The sheet is rendered by Playwright from a generated
`sheet.html` in the same folder (images load as sibling files).

### 2.2 `showtime lint <script>`

Pure checks over the script, plus timing checks over the timeline when a fresh take exists.
Each issue: `{ rule, level: 'warn' | 'info', where: 'scene#step' | 'script', message }`.

| rule | level | when |
|---|---|---|
| `caption-length` | warn | a caption has more than 6 words |
| `pause-for-loading` | warn | a `pause` of ≥ 1500 ms right after `click`, `press`, `type` or `select` (use `wait {for}`) |
| `show-ignored` | warn | `zoom`/`spotlight` on a step that has no target (`goto`, `press`, `wait`, `pause`, `scroll {by}`), or any `show` on a `setup` step |
| `no-intro` | info | `meta.title` is missing (no intro card) |
| `caption-too-short` | warn | a caption is on screen for less than `max(1200, 500 + 250 × words)` ms of output time (needs a take) |
| `video-length` | info > 60 s, warn > 120 s | output duration (needs a take) |

Human output lists issues and ends with `✓ no issues` or `N warnings, M notes`; without a fresh take
it adds `(record a take to also check timing)`. Exit code 1 when there is at least one `warn`.

### 2.3 `--json` on every command

| command | JSON on stdout |
|---|---|
| `check` | the `CheckReport` (unchanged) |
| `record` | `{ take, durationMs, steps }` |
| `render` | `{ video, durationMs }` |
| `frames` | `{ sheet, frames }` |
| `make` | `{ check, take: { take, durationMs, steps }, video: { video, durationMs } }`; on a failed check `{ check }` with exit 1 |
| `lint` | `{ issues, timing: boolean }` |
| `setup` | `{ links, browsers: boolean }` |

With `--json` nothing else goes to stdout (progress lines are suppressed); errors still go to
stderr as `✖ …` with exit 1.

## 3. Reliability

### 3.1 Hooks

```json
"hooks": {
  "before": [{ "run": "npm run db:reset" }, { "request": { "url": "http://localhost:3000/api/test/reset" } }],
  "after":  [{ "run": "npm run db:reset" }]
}
```

- `run`: a shell command, cwd = the script's folder, inherits the environment, 120 s timeout.
- `request`: `{ url, method = "POST", json?, headers? }`, 30 s timeout; any non-2xx status fails.
- `before` hooks run, in order, at the start of every `check` and every `record` (so `make` resets
  state between rehearsal and take); `after` hooks run when that `check`/`record` ends, success or
  failure. A failing `before` hook aborts with `hooks.before[i] (<what>) failed: <reason>` and the
  last lines of its output; a failing `after` hook is reported the same way.
- Hooks are not part of the action hash (they prepare the world; they are not recorded).

### 3.2 Network mocks (`app.mock`)

`[{ url, method?, status = 200, json?, body?, headers?, delayMs? }]`. `url` is a Playwright URL glob
(`**/api/reports*`). Matching requests are fulfilled with `json` (sent as `application/json`) or
`body`; `delayMs` waits before answering (keeps a spinner visible). A `method` that does not match
falls through to the network. Part of `app`, so part of the action hash.

### 3.3 Frozen clock (`app.clock`)

An ISO date-time string. `Date` returns that fixed time in the page; timers keep running
(Playwright `context.clock.setFixedTime`). Invalid dates fail validation.

### 3.4 Native dialogs (`app.dialogs`)

`"accept"` (default) or `"dismiss"` for `alert`/`confirm`/`prompt`/`beforeunload`. Before 0.3.0
dialogs were dismissed implicitly; demos that click "Delete" expect the confirm to pass.

### 3.5 Safe re-take

`record` writes into `.showtime/<name>/take.tmp` and swaps it in place of `take` only after the take
encoded successfully. A failed record leaves the previous take untouched; its `failure.png` is in
`take.tmp`.

### 3.6 Streaming requests do not stall settling

The network tracker ignores requests whose resource type is `eventsource`, or whose `Accept` header
asks for `text/event-stream`. Every step used to wait the full 3 s cap on pages with a live stream.

### 3.7 Relative `goto`

`goto.url` resolves against `app.url` (`"settings"`, `"/billing"`, `"?tab=2"`).

## 4. Polish

### 4.1 Captions never overlap

After captions are built, each caption ends no later than the next one starts. With the existing
220 ms fades this turns a hard swap into a quick dip.

### 4.2 Captions stay off the action

Each caption gets `position: 'bottom' | 'top'`. For a caption whose step has a target, the target
rect is projected into output pixels (window layout + camera) at the caption's start, middle and
end; if any projection reaches into the bottom band (y > 78 % of the output height) the caption
goes to the top. Steps without a target keep `bottom`. Top captions sit 3 % of the output height
below the top of the viewport (under the browser bar).

### 4.3 Outro card (`meta.outro`)

`{ title, subtitle?, url? }`. After the video the window fades out over its last 12 frames and an
outro card fades in for 2600 ms: logo (if any), title, subtitle, and the URL in an accent-bordered
pill, on the style background. QA shots gain `99-outro`.

### 4.4 Logo (`meta.logo`)

Path to an SVG, PNG, JPEG or WebP (≤ 2 MB), relative to the file that names it. Shown above the
title on the intro and outro cards (120 px tall at 1080p). The pipeline embeds it into
`timeline.json` as a data URI, so the renderer needs no extra files.

### 4.5 Brand file (`showtime.config.json`)

Looked up from the script's folder upward; the first one found applies.

```json
{
  "style": { "background": "…", "accent": "#16a34a", "address": "app.acme.com" },
  "meta": { "logo": "brand/logo.svg", "outro": { "title": "Try Acme free", "url": "acme.com" } }
}
```

`style` and `meta` are defaults: the script's own fields win key by key (`meta.outro` as a whole).
Unknown keys are an error. Paths inside the config resolve against the config's folder.

## 5. Contracts that change

- `Timeline` gains `outro: { title; subtitle?; url?; durationMs } | null` and `logo: string | null`;
  `Caption` gains `position: 'bottom' | 'top'`.
- `buildTimeline(script, events, opts)` takes `opts.logo?: string` (data URI).
- `WorkPaths` gains `takeTmp` and `sheet`.
- `LoadedScript` gains `config: string | null` (the brand file used).

## 6. Testing

Unit: schema (hooks, mock, clock, dialogs, outro, logo), config discovery and merge, caption
trimming and placement, rect projection, outro frames and QA shot, lint rules, hooks runner (real
`node -e` commands and a local HTTP server), sheet HTML escaping.
Integration: mocks + clock + dialogs + relative goto + SSE settle (steps), safe re-take (record),
outro and logo render + contact sheet (render), `--json` for every command and `lint` (cli).
