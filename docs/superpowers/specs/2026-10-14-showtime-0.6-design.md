# showTime 0.6.0: design

Status: approved for implementation. The user asked to keep improving after the LvivPak and voxa
demos; this release fixes what those two real recordings ran into. Builds on
[0.5.0](2026-10-13-showtime-0.5-design.md).

Not in 0.6.0: recording and replaying network traffic (HAR, WebSocket), locale matrices, timeline
dragging. Replay needs its own design for WebSocket streams and non-deterministic request bodies.

## 1. Capture

### 1.1 `app.hide`

CSS selectors of elements to hide in every take and rehearsal (`visibility: hidden`, so the layout
does not move): framework dev badges (`nextjs-portal`), chat widgets, cookie banners that `setup`
can't dismiss. Same mechanism and validation as `app.mask` (an invalid selector names its index).
Part of the action hash; an empty list leaves 0.5 hashes unchanged.

### 1.2 `app.reducedMotion`

`"reduce"` or `"no-preference"`, passed to the browser context. Sites that honour
`prefers-reduced-motion` then show scroll-reveal sections at once instead of animating them in, so
frames are not caught half-revealed. Part of the action hash (absent = unchanged).

### 1.3 `wait.timeoutMs`

`{ "do": "wait", "for": "…", "timeoutMs": 60000 }` (1–300 s, default 15 s) for pages that wait on
slow backends (AI calls, queues). Still sped up like any wait. Part of the action.

### 1.4 `server`

```json
"server": { "run": "npm run dev -- --port 3001", "url": "http://localhost:3001/", "timeoutMs": 90000 }
```

Top level (not part of the action hash). Before `check` and `record` (and the studio's Record),
showTime requests `url` (default `app.url`); if it answers, the running server is used. Otherwise
it runs `run` in the script's folder in its own process group, polls `url` every 500 ms until any
HTTP response arrives (`timeoutMs`, default 60 s), runs the work, and stops the process group
(SIGTERM, then SIGKILL after 5 s). A server that exits or times out fails with
`server (<run>) …` and the last lines of its output. Hooks run inside: server up → `before` → work
→ `after` → server down.

## 2. Direction

### 2.1 Captions last long enough to read

A caption stays on screen until the step settles and at least `max(1.5 s, 0.5 s + 0.25 s × words)`
of output time (the time `lint` already asks for), unless the next caption starts first.
`caption-too-short` then only fires when the next caption cuts one off.

### 2.2 A band for burned subtitles

With `subtitles: "burn"` in 16:9 and 1:1, the window shrinks to leave a band at the bottom (11 % of
the output height) and the subtitles are drawn in it, never over the app. Captions keep their
normal placement (bottom, or top when the target is low) inside the window. 9:16 is unchanged.

### 2.3 `audio.clips`

```json
"audio": { "clips": [{ "file": "calls/fire-1.wav", "at": "surge#3", "offsetMs": 400, "volume": 0.9 }] }
```

Sound files placed in the soundtrack at a step's start (plus `offsetMs`, ≥ 0): the app's own sounds
(a ringing phone, a caller's voice), which the screen capture can't hear. Paths resolve against the
file that names them and must exist at load; `at` must name a scene step (`scene#n`). Music ducks
under clips as under narration. Presentation only.

## 3. Output

### 3.1 `--scenes`

`render`/`make --scenes a,b` render only from the first listed scene's first step to the end of the
last listed scene (the cards are left out), for a short GIF or a teaser cut. Unknown ids fail and
list the scene ids. Subtitles in the `.srt` are cut and shifted to match.

### 3.2 `--fps`

GIF and WebP frame rate (5–30; defaults 15 and 20 as before).

## 4. Agent loop

### 4.1 `showtime inspect <url>`

Opens the page (headless, `--viewport`, default 1440x900), waits for it to settle and prints the
page title, every interactive element (button, link, textbox, searchbox, combobox, checkbox, radio,
switch, tab, menuitem, option excluded) with a ready target such as
`role=button[name="Request a Quote"]` and how many elements it matches, and the path of a
full-page screenshot (`.showtime/inspect/<host>.png` under the current folder). `--json` prints
`{ url, title, targets: [{ role, name, target, count }], screenshot }`. It replaces the ad-hoc
Playwright scripts an agent writes to explore an app.

### 4.2 `check --until scene#n`

Rehearse only up to and including that step (a step before an expensive part such as an AI call
surge). The report is `ok` when every rehearsed step passed.

## 5. Contracts that change

- `Script.app.hide: string[]`, `app.reducedMotion?`, `server?`, `audio.clips: Clip[]`,
  `wait.timeoutMs?`.
- `Timeline.clips: { index, atMs, volume }[]` (output ms from the video start);
  `Timeline.subtitleBand: number` (px; 0 when subtitles are not burned or in 9:16).
- `viewLayout(…, reserveBottom)`.
- `RenderOptions.scenes?`, `RenderOptions.fps?`; `CheckOptions.until?`.

## 6. Testing

Unit: schema and hash for the new fields; caption reading time; layout with a reserved band;
clip events; scene range; clip mixing; inspect's snapshot parsing; server option parsing.
Integration: hide and reducedMotion in a take (the element is invisible; a reduced-motion fixture
shows its final state); wait with a long timeout; check --until; server start, reuse and stop;
render --scenes (shorter video, trimmed SRT) and --fps; inspect on the fixture app; a render with
a clip has audio where the clip sits.
