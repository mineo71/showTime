# showTime 0.8.0: design — replay, locales, timing by hand

Status: approved for implementation (the user asked for all three: "давай всі"). Builds on
[0.7.0](2026-10-14-showtime-0.7-design.md).

## 1. Network record and replay

Apps that call paid or rate-limited APIs (voxa: Groq over HTTP, Cartesia over WebSocket) spend
quota on every rehearsal and take, and their timing varies run to run. Record the traffic once,
replay it after that: free, offline, and the same every time.

```json
"replay": { "file": "voxa.net.json", "match": ["**/api/**", "wss://api.cartesia.ai/**"] }
```

Top level, not part of the action hash. `match` are Playwright URL globs; `ws://`/`wss://` globs
route WebSockets, the rest route HTTP. `file` is relative to the script.

Modes, chosen with `--net` on `check`, `record`, `make` and the studio's Record:

| `--net` | what happens |
|---|---|
| `auto` (default) | replay when the file exists, else go live and record it |
| `live` | ignore the file, call the network |
| `record` | go live and (re)write the file |
| `replay` | the file must exist; requests it doesn't hold go to the network, counted in a warning |

The file is written only when the run succeeds, atomically.

**HTTP.** Recorded: method, URL, a hash of the request body, status, the response's content type,
the body (base64) and the latency. Replayed: the first unused entry with the same method, URL and
body hash; else the first unused entry with the same method and URL; else the last entry with the
same method and URL (re-served); else the network. Answers wait their recorded latency, so
spinners look as they did. Entries are consumed in order per key, so a 429 then a 200 replay as a
429 then a 200.

**WebSocket.** Recorded per connection, in order: the frames each way with their time. Client
binary frames are kept as sizes only (audio is large and the server's answers don't depend on
replaying it). Replayed without a server: connections pair with recorded ones in the order they
open (per URL without its query). A server frame is sent once the client has sent as many
messages as it had when the frame was recorded, and its delay after that message has passed; a
client text frame (a command such as `finalize`) also releases every frame recorded after its
twin. Recorded closes are replayed.

**Privacy.** No request headers are stored. Query parameters named like credentials (`token`,
`access_token`, `key`, `api_key`, `apikey`, `auth`, `sig`, `signature`, `secret`) are replaced by
`…` in stored URLs and ignored when matching. The file holds the API's answers: review it before
committing.

## 2. Locales

```json
"locales": ["en", "uk"],
"app": { "url": "http://localhost:3002/{locale}" },
"scenes": [{ "id": "quote", "steps": [
  { "do": "click", "target": { "en": "role=button[name='Request a Quote']", "uk": "role=button[name='Запит ціни']" },
    "show": { "caption": { "en": "A quote in one form", "uk": "Запит ціни в одній формі" } } }
]}]
```

- `locales` lists the languages; the first is the default.
- Any value in the script or brand file may be an object whose keys are all among `locales`: the
  value for the current locale is used. Missing one is an error naming the path and the locale.
- `{locale}` in any string is replaced by the locale code.
- Each locale is its own script: its own take (`.showtime/<name>.<locale>/`) and outputs
  (`<name>.<locale>.mp4`, `.srt`, …). Voices, captions, URLs and targets can all differ.
- `--locale <code>` selects one on every command (`check`, `record`, `render`, `frames`, `lint`,
  `make`, `studio`); default the first. `make --locales all|en,uk` and `render --locales …` run one
  locale after the other and report each.
- A script without `locales` works exactly as before.

## 3. Timing by hand (studio)

- **Speed by dragging.** Each step block on the timeline has a handle on its right edge; dragging
  it sets the step's `show.speed` so the step takes the dragged length (0.25–16×).
- **Caption length by dragging.** A caption track above the steps shows each caption as a bar;
  dragging a bar's right edge sets the new `show.captionMs` (its minimum time on screen, output ms).
- **Freeze.** New `show.freezeMs`: a still frame of this many output ms at the end of the step
  (presentation only: no new take), shown striped on the timeline, set in the inspector.

`captionMs` and `freezeMs` are presentation fields (not in the action hash). A caption still ends
when the next one starts.

## 4. Contracts that change

- `Script.replay?`, `Script.locales?`; localized values anywhere (resolved at load).
- `Show.captionMs?`, `Show.freezeMs?`.
- `loadScript(file, { locale? })`; `LoadedScript.locale: string | null`; work names and outputs
  carry the locale.
- `StepInfo.srcMs` (source length) for the studio's drag.

## 5. Testing

Unit: localization (paths, missing locale, `{locale}`, brand file), replay matching (keys, order,
fallbacks, secret stripping), WebSocket replay scheduling, caption length and freeze in the
timeline, edit whitelist.
Integration: a fixture with a counter API and a WebSocket: record, then replay with the server
gone and the same results; `--net live|record|replay`; `make --locales en,uk` on a two-language
fixture page writes two videos; the studio drag sets speed and caption length in the file.
