# showTime 0.5.0: design

Status: approved for implementation (item 6 of the improvement list; the user asked to "take the
others" and then to continue after 0.4.0). Builds on [0.4.0](2026-10-13-showtime-0.4-design.md).

## 1. Goals

1. **The AI writes, the human polishes.** `showtime studio <script>` opens a local page with a
   live player of the edited video, a timeline of the steps and an inspector. Changing a caption,
   a narration line, zoom, spotlight, speed or the look updates the preview in about a second and
   is saved back to the JSON script. Edits the agent makes to the file appear in the page live.
2. **Show it instead of writing it.** `showtime record-human <url>` opens a browser; the person
   clicks through the flow and closes the window; showTime writes a script with those steps.

Not in 0.5.0: dragging step boundaries or caption timing on the timeline (captions and holds stay
tied to steps), undo history beyond the file itself, editing setup steps, hooks or `app`.

## 2. Studio

### 2.1 Command

`showtime studio <script> [--port 4848] [--aspect 16:9|9:16|1:1] [--no-open]` starts a server on
`127.0.0.1`, prints `Studio: http://127.0.0.1:4848/` and opens it in the default browser. Ctrl+C
stops it. A busy port is an error that names `--port`.

### 2.2 Page

- **Player** (`@remotion/player` with the same `ShowtimeVideo` component the renderer uses, so
  the preview is the video), with the soundtrack.
- **Timeline** under the player: the intro, one block per step sized by its output time, the
  outro; icons for caption, narration, zoom and spotlight; a playhead. Clicking a block selects
  the step and seeks to it; the selected step follows the playhead while playing.
- **Inspector** for the selected step: `caption`, `say`, `zoom` (auto / off / 1–4), `spotlight`,
  `speed`, `hold` (marked "changes the take"). Text commits on Enter or blur, the rest on change.
- **Look** panel: `meta.title`, `meta.subtitle`, `style.accent`, `style.background`,
  `style.chrome`, `style.autoZoom`, `style.autoSpeed`.
- **Top bar:** the aspect switch (preview only; it is not saved), **Render** (MP4, GIF or WebP
  with the current aspect, progress in the page, the output path when done) and **Record**.
- **Banners:** an invalid script (shows the validation error, keeps the last good preview), a stale
  take (actions changed: offers **Record**), no take yet (offers **Record**).

### 2.3 Saving

An edit is `{ where: 'scene#n', show: {...} }`, `{ style: {...} }` or `{ meta: {...} }`; a `null`
value removes the key (an empty `show` is removed too). Only the fields above are accepted. The
edit is applied to the script as written on disk (brand-file defaults are not copied in),
validated with the brand file applied, and written atomically. The file is formatted with two-space
indentation and one step per line, the style of the examples. A failed validation writes nothing
and returns the error.

### 2.4 Live updates

The server watches the script and its brand file. Any change on disk (an agent editing the file,
the studio's own save) rebuilds the timeline (voices synthesized and cached, soundtrack mixed) and
pushes an event; the page reloads its state and keeps the playhead.

### 2.5 Server and security

`node:http` on `127.0.0.1` only. Routes: `/` (the page), `/app.js` (the client, bundled with
esbuild when the studio starts), `/api/state`, `/api/edit`, `/api/render`, `/api/record`,
`/api/events` (server-sent events), `/files/*` (the take and the soundtrack from
`.showtime/<name>/`, with HTTP range requests so the video seeks).

- Requests must carry `Host: 127.0.0.1:<port>` or `localhost:<port>` (no DNS rebinding).
- `/api/*` needs the token embedded in the page (`x-showtime-token`); a custom header also makes
  browsers preflight cross-origin requests, which the server never approves.
- `/files/*` serves only files inside `.showtime/<name>/`.
- One job (render or record) at a time; edits queue behind a running rebuild.

New runtime dependencies: `@remotion/player` (same version as Remotion) and `esbuild` (already
installed through `tsx`).

## 3. record-human

`showtime record-human <url> [-o <file>] [--viewport 1440x900]` opens a headed Chromium at the URL
and records clicks, typing, selects and key presses with Playwright's recorder (the programmatic
recording API Playwright's MCP uses; a missing API fails with a clear message). Each recorded
action prints as a line. Closing the browser window (or Ctrl+C) ends the recording and writes the
script (default `demo.json` in the current folder; an existing file is never overwritten without
`--force`).

Conversion:

| recorded | step |
|---|---|
| click (left) | `click` |
| click followed by fill on the same element, or fill | `type` with the final text |
| select | `select` with the first option |
| press | `press`, modifiers joined (`Meta+K`) |
| check / uncheck | `click` |
| navigate (typed URL) | `goto`, relative when on the same origin |
| right/double click, popups, file uploads | skipped, with a note on stderr |

Selectors become readable where Playwright's internal form has a public twin:
`internal:role=…` → `role=…`, `internal:text="x"i` → `text=x`, `internal:testid=[data-testid="x"s]`
→ `[data-testid="x"]`; others stay as recorded (they work as targets).

The script gets `app.url`, `app.viewport`, `meta.title` from the page title and one scene `flow`.
The output then goes through the normal loop: captions, `check`, `make`.

## 4. Contracts that change

- `ShowtimeVideoProps.assetBase?: string`: when set, media load from `<assetBase>/<path>` instead of
  `staticFile` (the studio serves them over HTTP).
- `stepFrames(timeline, steps)`: each step's first and last composition frame.
- `parseLoaded(raw, scriptPath)`: `loadScript` without the file read (the studio validates edits
  before writing).

## 5. Testing

Unit: edit application and its validation, the script formatter, step frames, the request guard
(host, token, file paths), recorded-action conversion and selector rewriting.
Integration: studio API over HTTP on a recorded fixture (state, edit writes the file, invalid edit
writes nothing, token and host checks, range requests, live update on an external edit); the studio
page in headless Chromium (player renders, a caption edited in the inspector lands in the file);
record-human driven headlessly on the fixture app, producing a script that passes `check`.
