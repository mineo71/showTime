# showTime 0.4.0: design

Status: approved for implementation (the user asked to "take the others": items 4–6 of the
improvement list). This release covers items 4 (sound) and 5 (formats). Item 6 (studio,
record-human) is 0.5.0 and gets its own spec. Builds on [0.3.0](2026-10-13-showtime-0.3-design.md).

## 1. Goals

1. **Pitches get sound.** A step can carry a narration line (`show.say`) that is spoken by a TTS
   engine. The video waits for the voice instead of talking over the next step. Optional music bed
   that ducks under the voice, optional click and typing sounds, and subtitles from the same text.
2. **One take, every format.** The same take renders as 16:9, 9:16 or 1:1, as MP4, GIF or WebP.
   Cropped formats follow the action with the camera instead of shrinking the window.

Not in 0.4.0: studio UI, record-human (0.5.0); per-locale renders; callouts and keyboard badges.

## 2. Script format

### 2.1 `show.say`

A string on any scene step. Narration starts when the step starts. It is presentation only: not
part of the action hash, so adding or editing narration never needs a new take. A `say` on a
`setup` step is flagged by the existing `show-ignored` lint rule.

### 2.2 `audio` (top level, presentation only)

```json
"audio": {
  "voice": { "engine": "system", "name": "Samantha", "speed": 1 },
  "music": { "file": "music/bed.mp3", "volume": 0.25 },
  "sounds": true,
  "subtitles": "file"
}
```

| field | default | meaning |
|---|---|---|
| `voice.engine` | `system` | `system` (macOS `say`, Linux `espeak-ng`), `openai`, `elevenlabs`, `command` |
| `voice.name` | engine default | voice name (`system`, `openai`) or voice id (`elevenlabs`, required there) |
| `voice.speed` | `1` | 0.5–2 |
| `voice.model` | engine default | `gpt-4o-mini-tts` (openai), `eleven_multilingual_v2` (elevenlabs) |
| `voice.instructions` | none | openai only: how to speak ("warm, confident") |
| `voice.command` | none | `command` only, required there: a shell command that reads the text on stdin and writes audio to `{out}` (a quoted `.wav` path, also in `$SHOWTIME_OUT`) |
| `music.file` | none | audio file ffmpeg can read, relative to the file that names it |
| `music.volume` | `0.25` | 0–1 |
| `sounds` | `false` | click and keystroke sounds |
| `subtitles` | `file` | `file`: an `.srt` next to the video; `burn`: also drawn on the video; `off` |

The brand file accepts `audio` too: the script wins key by key (`voice` and `music` as a whole).
`music.file` must exist at load time (`audio.music.file not found: …`).

Cloud engines read their key from the environment only (`OPENAI_API_KEY`, `ELEVENLABS_API_KEY`) and
send the narration text to that provider; nothing else leaves the machine. `OPENAI_BASE_URL` and
`ELEVENLABS_BASE_URL` override the endpoints (OpenAI-compatible servers, tests).

## 3. Sound

### 3.1 Synthesis and cache

Each distinct line is synthesized once and cached as
`.showtime/<name>/audio/voice-<hash>.wav` (48 kHz, loudness-normalised with ffmpeg `loudnorm`),
where the hash covers the engine settings and the text. `render`, `frames` and `lint` (when a take
exists) synthesize missing lines; nothing else does. Failures name the step:
`audio.voice (openai) failed for intro#2: HTTP 401 …`.

### 3.2 The video waits for the voice

A narration window runs from its step's start to the start of the next step with a `say` (or the
end of the video). When the line plus a 400 ms gap is longer than the window's output time, the
video holds a still frame for the difference at the last moment of the window when nothing moves
(no action, cursor move, ripple, camera move or fade), so a freeze never stops a move halfway. Holds
are the only change to pacing; speed-ups stay as they are.

`Segment` gains holds: `{ srcStartMs: t, srcEndMs: t, speed: 0, holdMs }` shows source time `t`
for `holdMs`. The timemap functions treat a hold as `holdMs` of output time; the renderer shows a
frozen frame.

### 3.3 Mix

The pipeline mixes one stereo 48 kHz track in TypeScript and the renderer plays it as a single
`<Audio>` (`.showtime/<name>/audio/mix.wav`, the length of the whole video including the cards):

- voices at their output times;
- music from the first frame, looped, faded in over 0.8 s and out over the last 2 s, ducked to 30 %
  while a voice plays (300 ms ramps);
- when `sounds` is on: a click per click and a tick per keystroke (keystroke times are now logged
  in the take; older takes spread them evenly over the `type` step), synthesized in code;
- a soft limiter keeps peaks under full scale.

`--no-audio` renders without the track. GIF and WebP never have audio. Silent outputs do not
synthesize narration at all (no voice needed, no holds) unless subtitles are burned in, where the
holds give the viewer time to read.

### 3.4 Subtitles

Each line is split into cues of at most 84 characters (two lines of 42), at sentence ends first,
then at commas, then between words; short neighbours then share a cue. Cue times are proportional
to their length. With `file` or
`burn`, `render` writes `<video>.srt` next to the video when there is narration. With `burn`,
cues are drawn at the bottom and every caption moves to the top.

## 4. Formats

### 4.1 Aspect ratios

`render`, `make` and `frames` take `--aspect 16:9|9:16|1:1` (default `16:9`): 1920×1080, 1080×1920,
1080×1080.

- **16:9** is unchanged: the whole viewport fits the window.
- **1:1** fills the padded square with the window; the viewport covers it, so the sides are
  cropped.
- **9:16** puts a window 1.3× taller than wide in the middle; the bands above and below hold the
  captions (bottom band; top band when subtitles are burned in, which then take the bottom band).

In the cropped formats the camera follows the action: every step with a target moves the focus to
it, and zooms only add depth beyond the crop's own magnification (`max(1, zoom × visible
fraction)`). Between targets the focus stays where it was.

### 4.2 GIF and WebP

`--format mp4|gif|webp` (default from the `-o` extension, else `mp4`). GIF: 15 fps, palette per
video; WebP: 20 fps, quality 76. Width defaults to 960 (16:9), 540 (9:16) or 720 (1:1); `--width`
overrides it. Default file names: `<name>.mp4`, `<name>-9x16.mp4`, `<name>-1x1.gif`, …

## 5. Lint

`narration-stretch`: a window holds the frame for more than 1.5 s (info) or 3 s (warn) while the
voice finishes: "shorten the line or slow the steps".

## 6. Contracts that change

- `Segment.holdMs?`, hold segments with `speed: 0`.
- `TakeEvents.keys?: number[]` (keystroke times, source ms).
- `Timeline` gains `aspect: '16:9' | '9:16' | '1:1'`, `narration: { where, text, atMs, durationMs }[]`,
  `subtitles: { startMs, endMs, text }[]`, `sounds: { kind: 'click' | 'key', atMs }[]`,
  `music: { volume } | null`, `audio: { src } | null`, `subtitlesBurned: boolean`. Audio and subtitle
  times are output ms from the start of the video (after the intro). `video.src` is relative to
  `.showtime/<name>/` (`take/raw.mp4`), which becomes the renderer's public folder.
- `buildTimeline(script, events, opts)` takes `opts.voices?: Record<where, durationMs>` and
  `opts.aspect?`.
- `--json` for `render`: `{ video, durationMs, subtitles: string | null }`.

## 7. Testing

Unit: schema and brand merge for `audio`; holds in the timemap; narration windows and holds;
subtitle cues and SRT; sound events; mixer (placement, ducking, looping, limiter); WAV
write/read; sfx synthesis; TTS cache keys; layouts for each aspect; generalised camera clamp and
projection; follow camera; lint rule.
Integration: TTS through `command` (ffmpeg sine) and `openai`/`elevenlabs` (local HTTP server);
`system` on macOS only; render with narration (audio stream present, video longer by the holds,
`.srt` written); 9:16 and 1:1 renders and stills; GIF and WebP outputs; CLI flags and JSON.
